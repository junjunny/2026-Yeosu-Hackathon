Fieldnote 발표 PPT용 핵심 문구
기준: 2026-11-08 / 현재 구현 코드와 실제 검증 결과

[슬라이드 1] 상담에서 현장 완료까지, 하나로 이어지는 농기계 AS
한 줄 메시지: 상담·검토·현장 수리 사이에서 끊기던 정보를 하나의 접수 기록으로 연결했습니다.
• 상담 접수 → 팀장 우선순위 확인·최종 컨펌 → 담당 기사 현장 처리 → 고객 최종 확인
• 상담 원문, ERP 확인 내용, 점검 결과, 견적, 사진, 서명을 한 접수에서 확인
• 오늘 접수와 오늘 방문 예약을 구분해 실제 업무 일정에 맞게 구성
추천 시각 자료: 5단계 업무 흐름도 + 실제 서비스 화면
발표 멘트: “단순히 질문에 답하는 챗봇을 넘어, 상담 이후의 업무까지 이어지도록 만들었습니다.”

[슬라이드 2] 역할에 맞춘 AI 지원
한 줄 메시지: 상담사는 고객 설명을 전달하고, 엔지니어는 필요한 순간에 도움을 받습니다.
• AgentStream 상담사 챗봇: ‘딱딱 소리가 나고 브레이크가 밀린다’와 같은 고객 표현 입력
• 엔지니어 Help: 현장 점검 중 궁금한 내용을 별도 대화 패널에서 질문
• Help를 열고 닫아도 작성 중인 체크리스트·점검 내용·서명 유지
• API 요청은 FastAPI 서버를 통해 전달하고 비밀키는 서버 .env에 분리
추천 시각 자료: 상담 답변 화면 + 작업 화면 옆 Help 패널
발표자 참고: AI 응답은 AgentStream을 사용하지만, 현재 진단 요약·출동 판단에는 코드의 규칙 기반 처리가 함께 포함됩니다. 전체 판단을 AI가 자동 확정한다고 설명하지 않습니다.

[슬라이드 3] 현장 수리 과정을 기록으로 남기다
한 줄 메시지: 점검부터 고객 확인까지, 단계별로 필요한 정보를 빠짐없이 남깁니다.
• 현장 도착 → 브레이크·타이어 필수 점검 → 수리 전 사진 → 수리 계획·견적
• 부품명 일부 검색, 부품 선택·수량 입력, 본사와 현장 주소를 이용한 출장비 자동 계산
• 수리 진행 동의 서명 → 수리 결과 → 수리 후 사진 → 개인정보 안내·최종 확인 서명
• 수리 전후 사진 각각 최대 5장, 작업 시각과 비용을 완료 보고에 함께 표시
추천 시각 자료: 견적서 + 사진 비교 + 손글씨 서명
발표자 참고: 부품 단가는 현재 가격표의 소비자가와 공임을 합산합니다. 출장비는 도로 거리 및 지역별 규칙을 적용하고, 지도 API 실패 시 보정 직선거리로 대체한 사실을 표시합니다.

[슬라이드 4] 내일 배차는 거리·시간 효율 중심으로
한 줄 메시지: 동일한 역량의 기사들에게 방문 순서를 조합해 효율적인 배차안을 제안합니다.
• Google OR-Tools로 여러 기사의 고객 방문 순서와 배정을 함께 계산
• 본점 출발, 기사당 최대 5건, 모든 기사 동일 역량, 우선순위가 높은 건의 미배정에 더 큰 비용 부여
• 고객 좌표 간 거리로 예상 이동시간을 계산하고 전체 이동 부담이 작은 배차안을 탐색
• 배차 결과는 네이버 Directions 5의 도로 경로와 지도 위에 표시
추천 시각 자료: “주소 → 좌표 → 예상 시간 → OR-Tools → 도로 경로 표시” 흐름도
발표 멘트: “기사 전문 분야를 나누는 대신, 동일 역량을 전제로 거리와 시간의 효율을 높이는 방식입니다.”
발표자 참고: 현재 계산은 Haversine 직선거리 × 1.3, 평균 40km/h 기반입니다. OR-Tools는 제한된 시간 안에서 좋은 해를 탐색하며 실시간 교통 기반 전역 최적해를 보장하지 않습니다. 본사 복귀 구간은 목적함수에 포함하지 않습니다. 시연 접수의 현장 전달과 내일 배차 최적화 화면은 별도 흐름입니다.

[슬라이드 5] 다른 기기에서도 이어지는 공유 기록
한 줄 메시지: 상담사 PC에서 시작한 접수를 팀장과 엔지니어가 각자의 기기에서 이어받습니다.
• 접수·상담·점검·견적·완료 상태: 서버 SQLite 데이터베이스에 저장
• 수리 사진·서명: 서버 파일로 보관하고 접수 기록에서 참조
• 다른 기기는 3초마다 변경 사항을 확인해 같은 접수 정보를 표시
• 접수별 저장 버전으로 동시 수정 덮어쓰기를 방지하고, 저장 실패·충돌 상태를 화면에 안내
• 이전 브라우저 기록은 재접속 시 이전하고, 다른 사본은 기존 서버 기록을 덮어쓰지 않고 별도 보관
추천 시각 자료: 상담사 PC / 팀장 태블릿 / 엔지니어 휴대폰 ↔ 공유 서버
발표자 참고: 실제 경로는 /data/Documents/Codex/.runtime/fieldnote/data/ 입니다. 역할 선택과 전송 대기 캐시는 브라우저에도 남습니다. 저장 완료 표시가 서버 저장의 기준입니다. 현재는 하나의 공유 데모 공간이며, 운영용 사용자 인증·권한 분리는 향후 적용 대상입니다.

[슬라이드 6] 팀장은 오늘 진행과 내일 계획을 구분해 확인
한 줄 메시지: 당일 현장 상황을 확인하면서 다음 방문 일정을 준비할 수 있습니다.
• 오늘 접수: 상담 내용과 우선순위를 검토하고 최종 컨펌
• 오늘 방문: 기사별 완료·예정 상태, 작업 시작부터 최종 서명까지의 기록 확인
• 내일 계획: 고객 후보와 기사별 방문 순서를 지도에서 확인
• 오늘·최근 7일·최근 30일의 완료 기록과 비용·현장 소요시간 비교
추천 시각 자료: 밝은 팀장 대시보드 + 기사별 진행 카드
발표자 참고: 위치 표시는 방문 주소와 최종 서명 시각에 근거한 진행 정보이며 실시간 GPS 추적이 아닙니다. 현장 소요시간은 대기·점검·수리를 포함하므로 기사 역량의 자동 점수로 설명하지 않습니다.

[슬라이드 7] 사용 기술과 구현·검증 도구
화면: HTML · CSS · Vanilla JavaScript — 모바일·태블릿·데스크톱 대응
서버: Python · FastAPI · Uvicorn — API 연동, 저장, 8501 서비스 제공
AI: AgentStream — 상담사 전용 / 엔지니어 Help 챗봇
지도·배차: 네이버 Geocoding · Directions 5 · Dynamic Map / Google OR-Tools
데이터: SQLite · 서버 이미지 파일 · 접수별 버전 관리
개발·검증: Codex · Git/GitHub · Python unittest · Node 테스트 · jsdom · Playwright
시연 이미지: imagegen 스킬 — 합성 수리 전후 사진과 손글씨 형태의 시연용 서명 제작
운영: runit — 작업 세션과 독립 실행, 서버 종료 시 자동 재시작
발표 멘트: “기능 구현뿐 아니라 서로 다른 기기의 업무 연결과 모바일 사용 흐름까지 검증했습니다.”
발표자 참고: 저장소에 설치된 다른 스킬의 존재만으로 사용 실적을 주장하지 않습니다. 생성 이미지·서명은 실제 고객 증빙이 아닌 합성 시연 자료로 표시합니다.
