## 최신 반영 사항

1. 고객 선택 목록 대신 이름(실구매자=실사용자)·등록 주소를 받습니다. 고장 발생 위치는 별도 필드입니다.
2. 상담 원문 전체를 참고하는 증상별 추가 질문을 제공합니다. 확인된 답변에 해당하는 일부 질문은 제외합니다. **실제 LLM이 아니라 합성 규칙 기반**입니다.
3. 기존 통화 종료 전 출동 항목 재확인과 종료 후 원문 잠금을 유지했습니다. 사고에서만 보험수리 가능 여부, 가능할 때만 가입 여부를 확인합니다.
4. 통화 종료 후 `erp-pending` 단계에서 상담사가 과거 수리 이력·제품명·구입 시점을 ERP 확인 후 직접 입력합니다.
5. 상담사/기사 A·B·C 선택과 팀장 역할을 추가했습니다. 팀장에서 실제 표시 이름을 바꾸고 접수 우선순위·기사 배정을 저장합니다. 역할 선택은 인증 기능이 아닙니다.
6. 엔지니어 체크리스트는 상담·분석 결과에 기반하며 브레이크·타이어 상태와 고객 확인 결과 기록을 필수로 받습니다.
7. 체크리스트 → **수리 전 사진 여러 장** → 부품·수량 채팅 입력 → 가격표 자동 계산 → 수리 진행 동의 서명 → 실제 수리 내역 → **수리 후 사진 여러 장** → 개인정보 안내 확인 + 수리 이행 확인 최종 서명 순서입니다.
8. 최종 견적은 출장비+부품비(소비자가+공임)입니다. 출장비는 나주 33,000원 / 전남 내 나주 외 60km 미만 **55,000원** / 60~100km 미만 77,000원 / 100km 이상 또는 전남 외 100,000원으로 확정되었습니다.
9. 원본 파밍보이 가격표는 아직 제공되지 않았습니다. 팀장에서 xlsx를 읽고 시트·제목 행·부품명·소비자가·공임 열을 확인해 등록하는 기능을 넣었습니다. 가격표가 없거나 부품을 특정할 수 없으면 견적을 차단합니다. 테스트용 금액을 실가격으로 넣지 않았습니다.
10. 팀장 동선은 지도 API/출발지가 미정이라 **연결 구조만** 구현했습니다. 출발지 저장, 기사 배정, 등록 주소·우선순위 기반 요청 계약과 응답 검증이 있습니다. API 미연결 상태에서 거리·시간·최적 동선을 만들지 않습니다.

## 출동 규칙

고객 방문 요청 → 주행 불가 → 정상 검색 결과 0건 → 유사 사례가 있고 자가조치 희망 → 상담사 선택 순서입니다. 검색 실패는 0건이 아니며 수동 판단합니다. AI 답변과 규칙 함수는 분리합니다.

이전 단일 사진은 배열로 복원하고 이전 견적은 기존 금액을 유지하며 표시합니다. 새 견적은 작성 당시 단가·가격표 출처를 저장합니다. 사진은 단계별 12장까지이지만 localStorage 용량에 따라 제한됩니다. 실제 기기 간 공유는 없습니다.

## 후속 수정 · 최신 사용자 요구 (위 항목보다 우선)

- ERP 3개 필드를 **통화 종료 전 재확인 화면**으로 이동했습니다. 필수 항목과 재확인 선택이 모두 유효해야 종료 버튼이 활성화됩니다. 기존 erp-pending 기록만 이전 흐름으로 처리합니다.

- 사용자 제공 부품 표 63개를 parts-catalog.js에 기본 등록했습니다. 소비자가+공임 합산, 명칭의 별표·쉼표와 비고를 보존합니다. 원본 xlsx 미제공 상태를 이유로 가격 입력을 더 이상 보류하지 않습니다.
- 개별 수동 배정을 제거했습니다. 전체 상담 종료+접수 완료 확인 후 출동 장소의 거리·시간으로 동선을 그룹화하고 가용 기사 이름을 무작위로 일대일 연결합니다. 지도 API가 없으면 배정하지 않습니다. 연결 계약은 README의 batchEndpoint를 확인하세요.
- 팀장 선택 시 전용 대시보드: 한국 시간 기준 오늘 완료/미완료(이월 포함), 기사별 목적지/작업 주소, 서명·완료 깃발 기록, 도착~최종 서명 소요시간·견적 기준 청구액을 표시합니다. 위치는 출동 주소 기반이며 실제 GPS/지도는 미연결입니다.

- 주최 측 8501 URL과 실행 명령은 README에 추가했습니다. 이 환경에서는 URL이 502였으며 주최 측 컨테이너에 직접 배포하지 않았습니다.
- 도메인 11개/DOM 흐름 테스트를 갱신했습니다. backend 파일은 변경하지 않았습니다.

## 최신: FastAPI + OR-Tools 지도 데모 (이전 무작위 배정/인증 요구보다 우선)

- 사용자 요청으로 로그인 없는 최소 데모로 변경. manager-access.demoMode=true이며 기존 팀장 화면에서 dispatch/로 연결합니다.
- frontend/dispatch/에 FastAPI, OR-Tools CVRP, 네이버 Geocoding/Directions 5 어댑터, 단일 지도 HTML, 합성 CSV 20건·기사4명을 추가했습니다. backend/는 건드리지 않습니다.
- 기사 전문파트·하루5건·긴급 패널티를 적용하고 더미 종료점으로 복귀를 생략합니다. 계산 중 외부 API 없이 Haversine×1.3/40km/h 행렬을 사용합니다. 확정 후 기사별 Directions 1회이며 재요청은 실행 결과를 재사용합니다.
- 주소 SQLite 캐시, 주소 오류 리스트, 합성 ID에 한정한 좌표 대체, 도로 실패 시 직선 경로, SDK 실패 시 SVG 좌표도를 지원합니다. 실제 입력 주소는 실패 시 좌표를 지어내지 않습니다.
- .env 키는 Git에 넣지 않습니다. HTTP 파일 허용 목록으로 Secret/CSV/Python/캐시를 제공하지 않습니다. JS 지도는 공개 Client ID만 config에서 받습니다.
- 상담 화면의 데모 버튼은 고객 A/B/C 단계별 합성 사례12개를 보존된 사용자 기록 옆에 생성합니다. 지도 CSV와 브라우저 상담 기록은 별도 입력입니다.
- AgentStream은 사용 서비스만 확인됐고 호출 URL/에이전트 ID/명세는 아직 없어 실제 RAG 연결은 보류입니다. API 키만으로 임의 서비스에 전송하지 않았습니다.
- 실행은 dispatch/README.md의 pip install → .env → uvicorn 3줄을 사용합니다. 정적 http.server로 지도 API는 실행되지 않습니다.

- FastAPI/배차 Python 테스트6개 및 키 없는 지도 HTML DOM 스모크 테스트 통과. 실제 제공된 키로 네이버 Geocoding 연결 성공을 확인했습니다. .env는 로컬에만 있으며 PR에 포함하지 않습니다.

- 실제 Directions 5도 공개 주소 간 1회 호출로 성공했습니다 (도로 경로선·거리·밀리초→초 변환 확인). 브라우저 지도 SDK 렌더링과는 별도 검증입니다.

## 최신 변경: 고정 본사·복귀·비밀번호·평가 참고 (이전 규칙보다 우선)

- 본사 고정: 전남 나주시 왕곡면 혁신산단6길9. 실제 Geocoding 좌표 [126.6928956,34.969903]. 모든 기사는 본사 출발→방문→본사 복귀입니다. CVRP 종료점과 Directions 도착, 대체 경로 모두 복귀를 포함합니다.
- 사용자는 전문파트 기사가 없다고 정정했습니다. 전문파트 제한을 제거했습니다. 모든 기사 동일 역량, 거리·시간·긴급도·하루5건만 반영합니다.
- 팀장 비밀번호는 서버 .env MANAGER_PASSWORD=1234. 난수 HttpOnly 쿠키 기반 세션·로그아웃·관리자 API 인증이 추가됐습니다. 초기 로그인 없는 요구는 최신 비밀번호 요구로 대체됐습니다.

- 실제 Chromium에서 네이버 /v3/auth가401로 거절되는 것을 확인했습니다. ncpKeyId/ncpClientId 모두 확인했고 Static Map도403이었습니다. 콘솔 계정 소유자가 Dynamic Map 사용과 등록 도메인을 확인해야 합니다. 서버 REST Geocoding/Directions 성공과 별개입니다.
- 이전 URL등록 안내의 포트 포함은 잘못된 안내였습니다. 공식 문제해결 문서대로 localhost/127.0.0.1/대표도메인을 포트·경로 없이 등록하도록 문서·화면을 수정했습니다. dispatch/README.md에 구체적 단계가 있습니다.
- 지도 인증 대기 동안 주소별 네이버 지도 검색 링크를 지원합니다. 지도 화면은 실제 위치·복귀·평가 실적의 출처와 한계를 명시합니다.
