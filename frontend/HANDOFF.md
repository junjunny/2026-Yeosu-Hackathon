# 원격 프로젝트 작업 인계 · 2026-11-07

## 작업 위치와 목적

- 저장소: https://github.com/junjunny/2026-Yeosu-Hackathon
- 사용자 담당 폴더: `frontend/`. 화면 코드뿐 아니라 사용자가 담당하는 모든 작업 파일을 모으는 공간입니다.
- 친구가 실제 회사 데이터를 가공하고 AgentStream/팀 API를 제공할 예정입니다. 현재 AgentStream 테스트 키 발급은 주최 측 오류로 지연 중입니다.
- 목표는 상담사의 전화 접수부터 엔지니어 현장 완료까지 **하나의 챗봇에서 역할을 바꿔 이어가는** 시연입니다.

## 가장 최근에 확정한 사용자 요구

1. 상담사는 수리 요청 전화를 받으면 통화 내용을 가공하지 않고 원문에 가깝게 채팅합니다. 챗봇은 데이터 근거가 있는 기술 답변을 생성합니다.
2. 통화가 끝나면 상담사 채팅은 읽기 전용입니다. 고객 방문 요청·주행 불가·자가조치 희망은 별도 필드로 확정합니다.
3. 엔지니어 화면 첫 부분에 전문 용어를 사용한 초기 기술 진단이 바로 보입니다. 상담사의 원문 대화와 챗봇 답변도 확인할 수 있습니다.
4. 엔지니어 과정은 챗봇이 먼저 질문하고 엔지니어가 하나씩 답합니다.
5. 순서: `도착` 입력 → 체크리스트 → 수리 예정 상세·부품·가격 → 고객의 수리 진행 동의 서명 → 수리 후 실제 작업 내용 → 비포·애프터 사진 → 정상 작동을 확인한 고객 최종 서명.
6. 수리 진행 동의와 최종 정상 작동 확인은 서로 다른 두 번의 서명입니다.
7. AI는 판단을 돕는 역할입니다. 출동 규칙을 적용하는 코드는 별도로 유지합니다. 확인하지 못한 정보는 `확인 필요`로 표시합니다.

출동 우선순위는 고객 방문 요청 → 주행 불가 → 정상 검색 결과 유사 사례 0건 → 유사 사례가 있고 자가조치 희망 → 그 외 상담사 선택입니다. 앞의 세 조건은 자가조치 희망보다 우선합니다. 검색 실패를 0건으로 간주하지 않습니다.

## 현재 코드 상태

- 별도 빌드가 없는 HTML/CSS/JavaScript 모듈입니다. 실행 명령은 `README.md`에 있습니다.
- 위 순차 흐름이 합성 데이터로 구현되어 있습니다. 엔지니어의 상담 원문은 펼쳐 볼 수 있는 영역에 보관합니다.
- `services.js`의 `replyToCounselor()`와 `buildAnalysis()`가 친구의 API로 교체할 호출 지점입니다.
- 현재 답변은 합성 사례 키워드 검색에 따른 고정 응답입니다. 실제 LLM/RAG 또는 AgentStream 연동은 없습니다.
- 고객·장비·사례·가격은 합성 데모입니다. 고객 이력은 같은 브라우저에 저장된 같은 고객 ID의 접수 기록에서 조회합니다.
- 저장은 `localStorage`(`yeosu-fieldnote-chat-v2`)입니다. 실제 기기 간 동기화, 서버 파일 저장, 사용자 인증은 연결 전입니다.
- 그림 서명 또는 성명 입력을 지원합니다. 사진과 서명은 브라우저 안에 저장합니다. 기존 브라우저에서 입력한 테스트 기록은 Git에 포함되지 않습니다.
- 초기 계획의 상담사 지시서 직접 편집 기능은 현재 최신 UI에 구현되어 있지 않습니다. 추가하려면 최신 순차 대화 요구와 함께 검토하세요.
- 지도·동선 최적화는 후순위입니다. 별도 사이트 호스팅은 진행하지 않았습니다.

## 보관한 개발 자료와 스킬

- `docs/development-plan.md`: 초기 개발 순서와 대회 자료 기반 계획. 최신 구현과 다른 부분은 이 문서와 `README.md`를 우선합니다.
- `.agents/skills/find-skills/`: 사용자가 요청한 Vercel 스킬 검색 도구.
- `.agents/skills/frontend-design/`: 화면 디자인에 적용한 스킬과 라이선스.
- `.agents/skills/web-design-guidelines/`: 접근성·사용성 점검에 적용한 스킬.
- `skills-lock.json`: 설치한 세 스킬의 원본과 해시.

스킬 설치·갱신 명령은 `frontend/`를 작업 디렉터리로 사용합니다.

## 검증 및 남은 일

JavaScript 구문과 출동 우선순위를 확인했고, 브라우저에서 상담부터 최종 서명까지의 전체 흐름, 새로고침 후 복원, 모바일 화면을 확인했습니다. 실제 데이터/API와 기기 간 공유는 검증 전입니다.

다음 작업은 사용자 UI 수정 요청 반영, 친구와 API 응답 형식·고객/장비 ID 합의, 실제 분석 및 저장 API 연결, 배포 환경에서 전체 시연 확인입니다. API 키는 서버에서 관리합니다.
