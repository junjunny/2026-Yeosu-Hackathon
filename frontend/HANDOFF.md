## 최신 반영 사항

1. 고객 선택 목록 대신 이름(실구매자=실사용자)·등록 주소를 받습니다. 고장 발생 위치는 별도 필드입니다.
2. 상담 원문 전체를 참고하는 증상별 추가 질문을 제공합니다. 확인된 답변에 해당하는 일부 질문은 제외합니다. **실제 LLM이 아니라 합성 규칙 기반**입니다.
3. 기존 통화 종료 전 출동 항목 재확인과 종료 후 원문 잠금을 유지했습니다. 사고에서만 보험수리 가능 여부, 가능할 때만 가입 여부를 확인합니다.
4. 통화 종료 후 `erp-pending` 단계에서 상담사가 과거 수리 이력·제품명·구입 시점을 ERP 확인 후 직접 입력합니다.
5. 상담사/기사 A·B·C 선택과 팀장 역할을 추가했습니다. 팀장에서 실제 표시 이름을 바꾸고 접수 우선순위·기사 배정을 저장합니다. 역할 선택은 인증 기능이 아닙니다.
6. 엔지니어 체크리스트는 상담·분석 결과에 기반하며 브레이크·타이어 상태와 고객 확인 결과 기록을 필수로 받습니다.
7. 체크리스트 → **수리 전 사진 여러 장** → 부품·수량 채팅 입력 → 가격표 자동 계산 → 수리 진행 동의 서명 → 실제 수리 내역 → **수리 후 사진 여러 장** → 개인정보 안내 확인 + 수리 이행 확인 최종 서명 순서입니다.
8. 최종 견적은 출장비+부품비(소비자가+공임)입니다. 출장비는 나주 33,000원 / 전남 내 나주 외 60km 미만 **55,000원** / 60~100km 미만 77,000원 / 100km 이상 또는 전남 외 100,000원으로 확정되었습니다.
9. 원본 파밍보이 가격표는 아직 제공되지 않았습니다. 팀장에서 xlsx를 읽고 시트·제목 행·부품명·소비자가·공임 열을 확인해 등록하는 기능을 넣었습니다. 가격표가 없거나 부품을 특정할 수 없으면 견적을 차단합니다. 테스트용 금액을 실가격으로 넣지 않았습니다.
10. 팀장 동선은 지도 API/출발지가 미정이라 **연결 구조만** 구현했습니다. 출발지 저장, 기사 배정, 등록 주소·우선순위 기반 요청 계약과 응답 검증이 있습니다. API 미연결 상태에서 거리·시간·최적 동선을 만들지 않습니다.

## 출동 규칙

고객 방문 요청 → 주행 불가 → 정상 검색 결과 0건 → 유사 사례가 있고 자가조치 희망 → 상담사 선택 순서입니다. 검색 실패는 0건이 아니며 수동 판단합니다. AI 답변과 규칙 함수는 분리합니다.

## 연결할 곳

- 상담 질문/분석: `services.js`의 `replyToCounselor()`, `buildAnalysis()`.
- 저장·조회/사진·서명/인증: 현재 localStorage를 쓰는 `loadState()`, `saveState()`를 실제 API로 교체합니다. 저장 키는 기존 `yeosu-fieldnote-chat-v2`를 유지합니다.
- 동선: `route-provider.js`의 `routeConfig.endpoint`. 지도별 호출과 비밀키는 팀 백엔드 어댑터에서 관리합니다. 요청/응답 계약은 README에 있습니다. 이번에는 backend를 수정하지 않았습니다.
- 가격표: 원본 xlsx를 받아 실제 시트·열·단가·부품 구분을 검증해야 합니다.
- 개인정보: 현재 안내는 시연용입니다. 실제 운영 정책을 받아 처리 주체·보유 기간·삭제 요청 방법 등을 확정해야 합니다.

이전 단일 사진은 배열로 복원하고 이전 견적은 기존 금액을 유지하며 표시합니다. 새 견적은 작성 당시 단가·가격표 출처를 저장합니다. 사진은 단계별 12장까지이지만 localStorage 용량에 따라 제한됩니다. 실제 기기 간 공유는 없습니다.
